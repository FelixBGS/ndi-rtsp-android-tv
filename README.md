# Низколатентная трансляция видео на Android TV (NDI / RTSP)

Проект для курсовой работы: система трансляции видеопотока (NDI-источник, веб-камера, рабочий стол или видеофайл) по локальной сети на Android-устройства (телевизоры, ТВ-приставки, смартфоны) с низкой задержкой (300–500 мс) и автоматической синхронизацией между несколькими экранами.

---

## Архитектура системы

```
    [Источник видео]
  (Камера / NDI / OBS)
           │
           │  Сжатие H.264 (один раз на ПК)
           ▼
     [ MediaMTX ]  ◄── discovery.py (UDP 8555: автопоиск и пинг)
     (RTSP Сервер)
           │
           │  RTSP over TCP (:8554/live) — раздача без перекодирования
           ▼
 ┌───────────────────┬───────────────────┐
 ▼                   ▼                   ▼
ТВ 1 (ExoPlayer)    ТВ 2 (ExoPlayer)    Телефон / Планшет
```

### Основные компоненты

1. **Сервер трансляции (ПК / Windows):**
   - **`server/mediamtx.exe`** — легковесный RTSP/RTMP сервер-мультиплексор ([MediaMTX](https://github.com/bluenviron/mediamtx)). Принимает один закодированный видеопоток и без дополнительной нагрузки на процессор раздает его десяткам клиентов по RTSP/TCP.
   - **`server/discovery.py`** — легковесный UDP-сервис автообнаружения. Отвечает на broadcast-запросы устройств в сети списком активных трансляций, их разрешением и кодеками, а также отвечает на пинги для замера сетевой задержки (RTT).
   - **`server/start-camera.bat`** — запуск всей серверной связки + захват веб-камеры через FFmpeg «в один клик».
   - **`server/start-test.bat`** — запуск сервера с тестовой синтетической таблицей и бегущими часами (удобно для демонстрации и проверки задержки).

2. **Клиентское приложение (Android):**
   - **`app-release.apk`** — готовый установочный файл (находится прямо в корне репозитория).
   - Написано на **Kotlin** с использованием **Jetpack Media3 (ExoPlayer)**.
   - Поддерживает Android 5.0+ (работает даже на старых ТВ-приставках).
   - Само находит трансляции в локальной сети, автоматически переподключается при сбоях и держит одинаковый буфер на всех устройствах (за счет плавной микро-подстройки скорости 0.9x–1.25x).

## КРИТИЧЕСКИ ВАЖНО: Настройка Wi-Fi сети (Изоляция клиентов)

Чтобы Android-устройство смогло увидеть компьютер и принять поток, они должны находиться в **одной локальной сети** и иметь возможность обмениваться пакетами напрямую.

> [!WARNING]
> ### Отключите «Изоляцию клиентов» на Wi-Fi роутере!
> 
> На многих домашних и университетских роутерах включена функция **AP Isolation** (в зависимости от производителя может называться: *«Изоляция беспроводных клиентов»*, *«Client Isolation»*, *«Station Isolation»*, *«Внутрисетевой обмен»*).
> 
> - **Что она делает:** Запрещает Wi-Fi устройствам взаимодействовать друг с другом. В результате телефон не сможет отправить UDP-запрос на ПК и не сможет открыть TCP-порт RTSP.
> - **Что нужно сделать:** Зайдите в панель управления роутером (обычно `192.168.1.1` или `192.168.0.1`), перейдите в раздел **Беспроводная сеть (Wi-Fi)** и **ОТКЛЮЧИТЕ** параметр **AP Isolation / Изоляция клиентов**.
> - **Гостевые сети (Guest Network):** Никогда не подключайте телефон или ПК к «Гостевой сети» роутера — в ней изоляция клиентов включена аппаратно и заблокирован доступ к локальным устройствам.
> - **Альтернатива (если нет доступа к настройкам роутера):** Раздайте Wi-Fi (точку доступа / Hotspot) прямо с ноутбука или смартфона и подключите оба устройства к этой сети.

## Быстрый запуск для демонстрации

### 1. Подготовка на ПК (Windows)

1. Откройте порты в фаерволе (нужно запустить **один раз от имени администратора**):
   ```cmd
   server\allow-firewall.bat
   ```
   *(Открывает входящие порты: TCP 8554 для RTSP, TCP 1935 для RTMP и UDP 8555 для автопоиска).*

2. Убедитесь, что установлен FFmpeg (проверить: `ffmpeg -version`). Если нет — установить одной командой:
   ```cmd
   winget install Gyan.FFmpeg
   ```

### 2. Запуск трансляции

- **Вариант А: Трансляция с веб-камеры (рекомендуется для демонстрации):**
  Запустите:
  ```cmd
  server\start-camera.bat
  ```
  *(Скрипт автоматически запустит MediaMTX, службу обнаружения и захват встроенной веб-камеры `"Integrated Camera"`).*
  Если используется отдельная USB-камера, можно передать её имя параметром:
  `server\start-camera.bat "USB Video Device"` (список камер: `ffmpeg -list_devices true -f dshow -i dummy`).

- **Вариант Б: Тестовая таблица с часами:**
  Запустите:
  ```cmd
  server\start-test.bat
  ```

- **Вариант В: Трансляция из OBS Studio или NDI-источника:**
  Инструкция по настройке находится в файле [server/OBS.md](file:///c:/Users/Ivan/Desktop/ndi-rtsp-android-tv/server/OBS.md).

В открывшемся окне консоли отобразится ваш локальный IP-адрес (например, `192.168.1.45`).

---

## 3. Запуск на Android

1. **Установка приложения:**
   - Возьмите готовый файл **`app-release.apk`** из корня репозитория и установите его на телефон или ТВ-приставку (через флешку, файловый менеджер или команду `adb install app-release.apk`).

2. **Просмотр:**
   - Запустите приложение **RTSP TV Player**.
   - На главном экране появится список обнаруженных источников в сети (обновляется каждые 5 секунд).
   - Выберите нужный поток нажатием на экран (или кнопкой `OK` на пульте ТВ).
   - Если роутер блокирует broadcast-пакеты, нажмите **«Ввести адрес вручную»** и введите IP-адрес компьютера (например, `192.168.1.45`, порт и путь `/live` приложение добавит автоматически).

3. **Управление и статистика:**
   - **Долгое нажатие (или кнопка «Вверх» / «Info» на пульте)** — открывает оверлей со статистикой реального времени:
     - фактический FPS декодирования;
     - входящий битрейт (Мбит/с);
     - сетевая задержка (RTT до ПК);
     - текущий размер буфера и отклонение от цели;
     - число отброшенных/пропущенных кадров.
   - **Короткое нажатие (или «OK» на пульте)** — возврат к списку источников.
   - **Кнопка «Меню» на пульте** — настройки (выбор целевой задержки буфера, автозапуск при старте ТВ-приставки, принудительный URL).

## Синхронизация между экранами (как это устроено)

Все телевизоры забирают один и тот же поток с одного сервера MediaMTX по протоколу RTSP через TCP. 
Синхронность обеспечивается программным джиттер-буфером в приложении:
- Если буфер телевизора начинает превышать целевое значение (например, 500 мс) — плеер плавно ускоряет воспроизведение (до 1.25x), сохраняя тональность звука, чтобы «догнать» эфир.
- Если буфер падает ниже нормы — плеер слегка замедляет видео (до 0.90x).
- Это гарантирует расхождение между экранами в пределах **±40–50 мс (1–2 кадра)** даже при работе по Wi-Fi.
